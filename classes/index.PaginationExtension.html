    Class PaginationExtension<TItem>

    Reads the total count with its own reader on every read, then adds the Pagination to the payload. Place it after the extensions whose contribution the count must consider (filters above all). The count reader receives the signal of the read, so it can hand it to fetch. By default it goes back to the first page when the query built by the previous extensions changes between two reads (PaginationExtensionOptions.resetPageOnQueryChange).

    Example

    const countUsers = (payload, signal) => api.countUsers(payload, { signal });
    const pagination = new PaginationExtension<User>(countUsers, 20, [10, 20, 50]);
    const dataSource = createDataSource(readUsers, { filtering, pagination });
    pagination.on("page", () => dataSource.read());
    await dataSource.read(); // countUsers(payload) then readUsers({ ..., pagination: { page: 1, itemsPerPage: 20, totalItemsCount } })
    pagination.goToNextPage(); // page event (if there is a second page), hence a new read
